# 格式规范

所有模式（创作、反推、多角色）的成品都遵守本规范。随模型变化的部分（tag 分组顺序、NL 句式与对照、token 上限）只写在 [模型档案.md](模型档案.md)。

---

## 一、硬规则

| # | 规则 | 说明 |
|---|---|---|
| 1 | 分隔符为 `", "` | 逗号后加一个空格。 |
| 2 | tag 全小写，下划线换成空格 | `blue_eyes` ➔ `blue eyes`。例外：用户给的 tag 原样保留（校验时放进 `--user-tags`）。 |
| 3 | 括号原样保留 | 助手自己写的 tag 不加转义：`hoshino (blue archive)`；用户给的 `\(` `\)` 原样保留。 |
| 4 | tag 必须在词表内 | 用 `tools/tag_vocab.py` 查词；词表外的换近义词或改写进 NL。用户给的除外。 |
| 5 | NL 每句是完整英文陈述句，以英文句号结尾 | tag 与 NL 之间空一行。 |
| 6 | 成品整体放进一个 ```text 代码块 | 说明写在代码块下方，最多两行。 |
| 7 | 权重语法少用 | 需要时写 `(tag:1.2)`；`[tag]`、`(tag)1.2` 不生效。 |
| 8 | token 不超过模型档案的上限 | 校验时传 `--token-limit`。 |

## 二、NL 规则

**什么时候写**：只在 tag 表达不了用户要的细节时写。tag 已经能描述画面，就不写 NL。

| 适合写 NL | 不写 NL |
|---|---|
| 分左右的局部特征：`She has a mole under her left eye.` | tag 里已有的服装、姿势、构图 |
| 人与物的具体关系：`She sits on the edge of the desk.`（词表无对应 tag 时） | 氛围、情绪、「画面很美」 |
| 哪只手做什么：`She holds the umbrella in her left hand.` | 光影修辞：`golden light gently bathes...` |
| 多角色的外貌、动作归属与互动 | 把 tag 换个说法再写一遍 |

**怎么写**：

- 一句一件事：主语 + 动作/位置 + 对象；
- 形容词只留能区分画面的：颜色、左右、大小、数量；
- 不用比喻、不叠形容词、不写副词修饰（`gracefully`、`gently`、`softly`）；
- 单人用 she/he；多人用名字或稳定指称，避免指代不清。

各模型的句式细节与 ❌/✅ 对照见模型档案。

## 三、不写的内容

判断标准：**写进去的每样东西，画面上都找得到吗？** 找不到的不写。

| 不写 | 说明 |
|---|---|
| 质量词（`masterpiece`、`best quality`、`score_9`……） | 各模型的质量串不同，交给用户。用户自己给的原样保留。 |
| 人物 tag | 不主动写；用户给的原样保留。反推时打标器的人物候选写在代码块下方。 |
| 画师名、单独的作品名 | 作品出处跟着角色名走（`hoshino (blue archive)`）。 |
| 负面提示词 | 只交正面提示词。 |
| 镜头外的东西 | 相机、拍摄者、机位架在哪——模型会照字面画出来。视角用 `from above`、`from side` 等构图 tag 表达。 |
| 负向句 | 「画面里没有××」反而会把××画出来；不提即可。 |
| 看不见的心理与因果 | 「她正准备离开」「因为刚下过雨」——只写这一刻看得见的。 |
| 分级标签 | 助手不写 `general`、`sensitive`、`questionable`、`explicit`，打标结果里的也会被校验器移除；用户自己给的原样保留。 |

## 四、超出 token 上限

按顺序精简，每次改完重跑校验：

1. 删 NL 里可有可无的句子，合并能合并的句子；
2. 删次要场景、背景 tag 和同义堆叠的 tag；
3. 保护用户明确要求的服装、姿势、构图、外貌与触发词；锚点本身就超限时，问用户保留哪些。
