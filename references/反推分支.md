# 反推分支（图片 ➔ tag）

用户发来图片要反推时进入本分支。打标器给出一长串带置信度的 tag，助手要看图把它精选成用户真正需要的那一组：用户审一份精炼的清单，比审打标器的原始输出省力得多。

---

## 一、流程

```text
1. 打标 ──── pixai_tagger 输出带置信度的 JSON
2. 看图精选 ─ 按置信度分档，对照原图决定去留；重点核对服装、姿势、构图
3. 补漏 ──── 打标器漏掉的明显服装/姿势/构图，查词表后补上
4. 校验 ──── anima_validate 比对词表、折叠、计数
5. 交付 ──── 一个 text 代码块；人物候选和存疑项写在代码块下方
```

## 二、打标

```powershell
New-Item -ItemType Directory -Force -Path "$SKILL\.work" | Out-Null
& $PY "$SKILL\tools\pixai_tagger.py" "<图片路径>" --json | Out-File "$SKILL\.work\run.json" -Encoding utf8
```

多张图一次传入，只加载一次模型。JSON 里 `general` 与 `character` 带置信度；`copyright`、`style`、`meta`、`rating` 不进成品。

## 三、看图精选（按置信度分档）

| 置信度 | 怎么处理 |
|---|---|
| ≥ 0.6 | 默认保留；看图时只排除明显误报。 |
| 0.35 ~ 0.6 | 逐个对照原图：看得见就留，看不清或不确定就删。 |
| < 0.35 | 默认删除；只有看图能确认、且属于服装/姿势/构图的才留。 |

阈值是参考，最终以画面为准。精选时：

- **服装、姿势、构图逐项核对**：衣服的颜色/款式/长短/花纹是不同的属性轴，都留（`blue skirt, pleated skirt, plaid skirt, miniskirt` 不是重复）；姿势要和画面一致（坐/站/跪只留一个主姿势）；景别和视角打标器常漏，要看图确认。
- **删噪声**：打标器常给出的泛化词与看不出来的细节——画面上找不到的物件、背景里无关紧要的小东西、同义堆叠——删掉。
- **外貌单独一组**：发型、发色、瞳色等放在一行，方便用户换成自己的角色时整行删掉。
- **人物候选不进成品**：`character` 里的角色名写在代码块下方一行，供用户自己决定；即使认得出画的是谁，也不往 tag 里写。用户明确说「这是 xx」时，按用户说的写。
- **补漏**：打标器漏掉、但画面上清楚可见的服装/姿势/构图，先 `tag_vocab.py search` 查到词表里的 tag 再补，并在下方说明补了哪些。

单人图直接看整图，不要裁切；多人图转 [多角色模式.md](多角色模式.md)，必要时裁切核对各人的服装与姿势。

## 四、要不要写 NL

默认只交 tag。只有画面里有 tag 表达不了、又是这张图关键的东西（某只手放在哪里、谁拿着什么递给谁）才补 NL，写法见 [模型档案.md](模型档案.md)。不要用 NL 把 tag 再描述一遍。

## 五、校验与交付

```powershell
& $PY "$SKILL\tools\anima_validate.py" --tags "<精选后的 tag 串>" --token-limit 512
```

退出码 0 才交付。打标器输出的 tag 一般都在词表内；报「词表外」的多半是补漏时写错了，换成近似词。

```text
1girl, solo,

short hair, blue hair, blue eyes,

raincoat, see-through clothes, hood, blue shirt, pleated skirt, blue skirt,
hair flower, transparent umbrella, white footwear, sneakers,

standing on one leg, holding umbrella, outstretched arm, light smile, looking at viewer,

full body, from below, dutch angle,

outdoors, rain, puddle, rainbow, backlighting,
```
人物候选：无。补充：`from below`（打标器漏检）。

代码块下方最多两行：人物候选、补了什么、哪些存疑。
