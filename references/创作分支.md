# 创作分支（中文需求 ➔ tag / NL）

用户只给了文字需求、画面里只有一个主体时进入本分支。两个及以上角色转 [多角色模式.md](多角色模式.md)。

下面以 tag 为主的模型（如 Anima）为例；以 NL 为主的模型按模型档案调整。

---

## 一、拆需求

把用户的话拆到下面几栏，**服装、姿势、构图三栏是重点**：

| 栏 | 内容 | 写法 |
|---|---|---|
| 人数 | `1girl, solo` / `1boy, solo` | tag |
| 角色 | 用户给的角色名、触发词、角色 tag 块 | 默认原样保留，见下方说明 |
| 外貌 | 发型发色、瞳色、体型 | 用户给了就沿用，没给不主动补 |
| **服装** | 上衣、下装、鞋袜、饰品、手持物 | tag 尽量拆到颜色、款式、长短、材质 |
| **姿势** | 站坐躺跪、手的位置、表情、视线 | tag；tag 说不清的部位关系写 NL |
| **构图** | 景别、视角、主体朝向 | tag：`full body`、`cowboy shot`、`from above`、`from side`…… |
| 场景 | 地点、时间、天气、光线 | 只写用户提到的或画面必需的 |

**用户贴来的角色 tag 块**（外貌、服装，以及 `"G41" is written on the chest` 这类句子型描述）默认整块原样保留，包括转义括号、引号和分级词，校验时整块放进 `--user-tags`。助手只在两种情况下改动：一是与本次场景需求冲突，例如需求要光腿，就删掉 `single thighhigh` 这类腿部服装；二是在本次构图里看不见，例如 `from behind` 时删掉胸前文字、`name tag`、`covered navel` 这类正面特征，而头发、耳朵、发饰这类背面也看得见、能认出角色的特征保留。拿不准的项（比如侧脸能否露出瞳色）交给助手按画面判断。改了什么，在代码块下方用一行说明。

用户没说的栏：服装、姿势、构图可以补一组合理的选择；外貌、场景、光影不主动加戏。

## 二、按需求的明确程度交付

| 用户说了多少 | 怎么交 |
|---|---|
| 很具体（「白发修女，黄昏废墟里跪地祈祷」） | 照着写一条，不加用户没说的设定。 |
| 只有主体（「来个猫耳女仆」） | 补服装、姿势、构图交一条，代码块下一行说明补了什么。 |
| 只有方向（「夏日清凉感」「随便来张」） | 给 2~3 条方案，差别放在服装、姿势、构图上。 |

不要空手反问：信息再少也先交一版，再在下方一行说明可以怎么改。

## 三、查词

先凭经验写出整串草稿，用一次 `check` 批量比对；只对报「词表外」或拿不准的概念单独 `search`：

```powershell
& $PY "$SKILL\tools\tag_vocab.py" check "standing, kitchen, bento, from behind, doorway"
& $PY "$SKILL\tools\tag_vocab.py" search door frame
```

- 结果按帖子数排序，优先选帖子数高、含义正对的；
- 同一概念有多个近义 tag 时，选一个最贴切的，不要全堆上去；
- 查不到合适的 tag ➔ 这个概念改写进 NL。

## 四、决定要不要写 NL

逐条问：**这件事 tag 能表达吗？**

| 需求 | tag 能表达？ | 写法 |
|---|---|---|
| 「坐着，翘二郎腿」 | 能 | `sitting, crossed legs` |
| 「坐在桌子上」 | 能（`sitting on desk` 是别名，词表规范名为 `on desk`） | `sitting, on desk` |
| 「坐在桌子边缘，腿垂在外面」 | 边缘与腿的位置 tag 说不清 | `sitting, on desk` + `She sits on the edge of the desk with her legs hanging down.` |
| 「左眼下有颗痣」 | `mole under eye` 不分左右 ➔ 不完全能 | tag + `She has a mole under her left eye.` |
| 「一只手撑着下巴，另一只手拿着笔」 | 部分能 | `head rest, holding pen` + `She rests her chin on her left hand and holds a pen in her right hand.` |
| 「阳光很温暖的草地」 | 能 | `field, sunlight`，不写 NL |

全部能用 tag 表达时，成品只交 tag。NL 的句式与 ❌/✅ 对照见模型档案。

## 五、组装与校验

按模型档案的 tag 顺序分组排列，整体放进一个 ```text 代码块：

```text
1girl, solo,

white hair, long hair, red eyes,

nun, habit, veil, rosary,

kneeling, own hands clasped, looking up,

full body, from side,

ruins, church, dusk,
```

交付前跑校验（用户给的 tag 全部放进 `--user-tags`）：

```powershell
& $PY "$SKILL\tools\anima_validate.py" --tags "<tag 串>" --nl "<NL>" --token-limit 512 --user-tags "<用户给的>"
```

退出码 0 才交付。词表外的 tag 按校验器给的近似词替换，或改写进 NL。

## 六、自查

| 检查 | 要求 |
|---|---|
| 质量词、人物 tag | 没有主动写；用户给的原样保留 |
| 服装、姿势、构图 | 每栏都有，且拆到了颜色/款式/视角这一级 |
| 用户锚点 | 用户给的 tag 和说的特征都在；删改过的（冲突、看不见）已在代码块下方说明 |
| NL | 只写 tag 说不清的；没有复述 tag；没有修辞形容词 |
| 裸露 | 全裸时不写任何服装 tag |
| 画外之物 | 没有相机、拍摄者、负向句、看不见的心理 |
